- feat(uploads): derived files (variants) for thumbnails, previews and poster
  frames (experimental) by @Tobbe

`@cedarjs/uploads` can keep track of files made from other files: thumbnails,
a PDF's drawn first page, a video's poster frame. The file they're made from
can be an upload or a file stored elsewhere, such as a document fetched from a
third-party API. Declare them with `defineDerivedFiles()`: pluggable sources
(`uploadSource()`, or any `{ key?, read }`) and one generator function per
variant name. Each made file is an ordinary `Upload` row, and its bookkeeping
lives in an opt-in `DerivedFile` table.

`acquireVariant({ upload: id }, 'thumb-164')` makes a missing file on first
request, by one process at a time, and reports `pending` while another process
is making it. A generator that throws is retried after 1 minute, 5 minutes, 30
minutes, 2 hours and 6 hours (`retryDelays`); one that returns `null` is
remembered as failed until `resetVariants(name)`. A source file that doesn't
exist, such as an upload id with no row, throws an `UploadError` with code
`NOT_FOUND` and is not remembered.
`deleteFor(source)` deletes a source file's derived files, and `deleteFile()`
with `derivedFiles` does it for uploads.

The package makes no images itself and depends on no media libraries. See
"Derived files" in the uploads docs. It is experimental and may change.
