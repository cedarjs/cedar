- feat(jobs): declared recurring schedules and unique job keys (#3021) by @Tobbe

Jobs can declare the recurring schedules they run on, next to the rest of the
job, and every job worker syncs them when it starts: missing schedules are
added, changed ones updated and ones that are no longer declared removed. There
is no script to run after changing a schedule. Each schedule has a key, so one
job can run on several schedules with different arguments, and the arguments are
type checked against `perform()`.

```ts
export const ReportJob = jobs.createJob({
  queue: 'default',
  schedules: [
    { key: 'hourly', cron: '0 * * * *', args: ['summary'] },
    { key: 'nightly', cron: '0 3 * * *', args: ['full'] },
  ],
  perform: async (kind: 'summary' | 'full') => {
    // ...
  },
})
```

`later()` takes a `key`. While a job with that key is still queued, no new job
is added and the queued one is returned with `alreadyQueued: true`. A job
releases its key when a worker picks it up, so work requested while it runs is
queued again. The database's unique constraint makes this hold across processes.

```ts
const job = await later(RefreshThumbnailsJob, [page.id], {
  key: `thumbnails:${page.id}`,
})
```

Both features need a new column on the `BackgroundJob` model. Add
`key String? @unique` to it and run `yarn cedar prisma migrate dev`. Apps
without the column keep working as before until they use a key or declare a
schedule. See the Background Jobs docs for the details, and for a pattern for
long jobs that continue later.
