- fix(deploy): Netlify skew protection never pins page loads (#2920) by @Tobbe

Netlify skew protection pins only build assets (`/assets/*`) and API routes to
the deploy a client loaded its page from. Page loads are always served by the
latest deploy and update the `cedar-skew-token` cookie, so reloading always gets
the newest version, and a "new version available, please reload" prompt works as
expected.

- The cookie is set only on HTML responses. Asset and API responses from a
  pinned deploy don't renew it.
- The pinned API routes come from `cedarUniversalDeployPlugin()`, so they follow
  whatever API root path is configured.
- The edge function that sets the cookie on static HTML doesn't run for assets
  and API routes.
- `cookieMaxAge` defaults to 24 hours. It only bounds how long an open tab can
  keep loading chunks from the deploy it started on.
