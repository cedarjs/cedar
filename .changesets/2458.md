- fix(gql): Trusted Documents 500s on every non-persisted request (#2458)
  by @ladderschool

With `trustedDocuments = true`, a Cedar app could not log in, and every
non-persisted operation came back as `INTERNAL_SERVER_ERROR` instead of the
intended `Use Trusted Only!` error:

```
TypeError: Body is unusable: Body has already been read
    at _Request.text (node:internal/deps/undici/undici)
    at allowCedarAuthCurrentUserQuery (useCedarTrustedDocuments.js)
```

The Trusted Documents allow-list — the one that lets the Cedar Auth
`currentUser` query and the Studio mail-resync mutations through without a
persisted document — read the request body with `await request.text()`. By the
time it runs, Yoga has already consumed that body to build the GraphQL params,
so the second read throws (and `request.clone()` throws too, because the body is
already disturbed). Since `useCurrentUser` posts
`query __CEDAR__AUTH_GET_CURRENT_USER { cedar { currentUser } }` on every page
load, authentication never resolved.

The allow-list now matches against the already-parsed `params.query` instead of
re-reading the body. Along the way, the two allow-list helpers became
synchronous, which fixes a second bug: they used to be `async`, so
`allowCedarAuthCurrentUserQuery(request) || allowCedarStudioResyncMailMutations(request)`
short-circuited on the first (always-truthy) Promise and the Studio branch never
ran.

No action needed in your app — if you had Trusted Documents turned off because
logging in was broken, you can turn it back on.
