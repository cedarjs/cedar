- fix(vite): Cells now preserve React Fast Refresh by @lisa-assistant

The Vite Cell transform (`vite-plugin-cedar-cell.ts`) assigns `createCell` and
`createServerCell` call results to named `const` bindings before default-exporting
them, enabling React Fast Refresh to recognize Cells as refresh boundaries:

```js
const MyCell = createCell({ QUERY, Loading, Success, displayName: 'MyCell' })
export default MyCell
```

This preserves component state during edits in dev mode. Previously, anonymous
default exports of call expressions prevented Fast Refresh from registering a
component as an HMR boundary, forcing full remounts of the nearest refresh-eligible
ancestor (typically the Page) and discarding any state in the Cell's subtree.

This is a build-output-only change — Cell authoring is unaffected. Cell filenames
should be valid JavaScript identifiers in PascalCase (as generated Cells always
are); an invalid or colliding filename will still surface as a build error from
the underlying JS parser, just without a Cedar-specific message.

Note: this only fixes the Vite dev/build transform. The sibling implementations
used for prerendering (`@cedarjs/prerender`'s `rollup-plugin-cedarjs-cell.ts`)
and Jest tests (`@cedarjs/testing`'s `babel-plugin-redwood-cell.js`) are outside
this change's scope; bringing them in line is a possible follow-up for consistency.
