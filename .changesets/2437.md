- fix(vite): Cells no longer break React Fast Refresh by @lisa-assistant

The Vite Cell transform (`vite-plugin-cedar-cell.ts`) used to wrap a Cell's
exports directly in an anonymous default export:

```js
export default createCell({ QUERY, Loading, Success, displayName: 'MyCell' })
```

React Fast Refresh requires a named binding to register a component as an
HMR boundary. An anonymous default export of a call expression is exactly
the shape it declines to handle, so editing a Cell forced a full remount of
the nearest refresh-eligible ancestor (typically the Page), discarding any
state held in the Cell's subtree.

The transform now assigns the `createCell`/`createServerCell` call to a
named `const` (using the Cell's own PascalCase name, e.g. `MyCell`) and
exports that binding by reference instead:

```js
const MyCell = createCell({ QUERY, Loading, Success, displayName: 'MyCell' })
export default MyCell
```

This is a build-output-only change — Cell authoring is unaffected.

Note: this only fixes the Vite dev/build transform. The sibling
implementations used for prerendering (`@cedarjs/prerender`'s
`rollup-plugin-cedarjs-cell.ts`) and Jest tests (`@cedarjs/testing`'s
`babel-plugin-redwood-cell.js`) still produce an anonymous default export.
Fast Refresh only applies in the Vite dev server, so those are left
unchanged for now; bringing them in line is a possible follow-up for
consistency.
