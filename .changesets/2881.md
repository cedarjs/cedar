- fix(jobs): Reset a cron job's attempts after each successful run (#2881) by
  @Tobbe

A recurring (cron) job's `attempts` count is reset to 0 after every successful
run. `maxAttempts` and the retry backoff apply to consecutive failures of a
single run, so a long-running recurring job isn't permanently failed by one
failed run.

When a recurring job does fail `maxAttempts` times in a row, or a run exceeds
`maxRuntime`, the worker logs an error saying its schedule has stopped. Call
`later(job, args, { cron })` again to restart it.

The `PrismaAdapter` only records a job's outcome while the job is still locked
by the claim that ran it (matched on `lockedAt`), so a stalled worker's late
result can't change a newer run of the same job.

Custom adapters should reset `attempts` in `success()` when `runAt` is set. The
attempt that reaches `maxAttempts` is recorded with a single `failure()` call
that includes the attempt's `error`, without a preceding `error()` call.
