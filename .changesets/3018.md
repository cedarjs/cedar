- feat(api): Run untrusted input in a locked-down child process
  (`@cedarjs/api/sandbox`) (#3018) by @Tobbe

`@cedarjs/api/sandbox` runs a Node script on untrusted bytes, like an uploaded
photo or a third party's PDF, in a sandboxed child process. If a crafted file
exploits a bug in the parser (libvips, pdf.js, …), it lands in a process with an
empty environment that can read only its own script and the packages it needs,
and can't write files, start processes or `eval`. The child gets the input on
stdin and returns its result on stdout, with a heap cap, a timeout and input and
output limits.

```ts
import {
  createConcurrencyLimiter,
  runSandboxedChild,
  sandboxReadPaths,
} from '@cedarjs/api/sandbox'

const limit = createConcurrencyLimiter(2)

const result = await limit(() =>
  runSandboxedChild({
    script: path.join(import.meta.dirname, 'thumbnail.child.js'),
    readable: sandboxReadPaths(['sharp'], { from: import.meta.url }),
    allowAddons: true,
    input: bytes,
  }),
)
```

It builds on Node's permission model and is defense in depth, not a security
boundary: it doesn't constrain native code, and on Node 24 it doesn't restrict
network access. See `packages/api/src/sandbox/README.md`.
