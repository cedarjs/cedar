- fix(build): Rewrite `.ts` import specifiers in the api build output (#2445) by
  @ladderschool

The api build compiles every source file to `.js` but left import specifiers
untouched, so a file that imported another _by its TypeScript extension_ ended
up in `api/dist` requiring a file that isn't there:

```
Error: Cannot find module '../../lib/greet.ts'
- api/dist/services/userExamples/userExamples.js
```

`cedar build api` succeeded; `cedar serve api` and `cedar dev` then crashed on
boot.

`.ts` specifiers aren't exotic — the app template's `api/tsconfig.json` sets
`allowImportingTsExtensions`, and Prisma's `prisma-client` generator emits them
throughout its output when the schema sets `importFileExtension = "ts"`, so an
api that generates its client into `api/src` gets a `dist` full of them.

Relative `.ts`/`.mts`/`.cts`/`.tsx` specifiers are now rewritten to `.js` on
both api build paths, and a build that somehow still emits one fails with the
offending files listed rather than producing a `dist` that only breaks when you
run it.
