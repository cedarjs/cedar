- feat(tenancy)!: roles from the current organization, and fail closed (#3159)
  by @Tobbe

In an app with tenancy, `@requireAuth` and `requireAuth()` are about the
current organization: they need one, and check the user's role in it. Fields
about the signed-in user rather than an organization say so with
`@requireAuth(scope: USER)`. `useAuth().hasRole` inside an `OrgScope` checks
the role in that organization too, and `OrgScope` takes `roles` and
`unauthorized` to guard routes by it.

`createTenancyAuth({ defaultRoles })` from `@cedarjs/tenancy` gives an app's
`api/src/lib/auth.ts` its `hasRole`, `requireAuth` and `hasOrgRole`.
`defaultRoles` is what a check that lists no roles admits, so a role added
later is refused everywhere until a field lets it in. `yarn cedar setup
tenancy` sets this up.

`@requireMembership` and `requireMembership()` are removed. To upgrade an app
set up with them, see "Upgrading from `@requireMembership`" in the tenancy
docs.
