- feat(router)!: tenancy on the Router, no OrgScope wrap (#3198) by @Tobbe

The router renders the organization provider itself, so organization routes go
in a `PrivateSet` with no `OrgScope` in its `wrap`. `<Router useOrgRoles>` is
replaced by `<Router tenancy>`, with the `tenancy` from `createTenancy` in
`@cedarjs/tenancy/web`:

```tsx title="web/src/tenancy.tsx"
import { createTenancy } from '@cedarjs/tenancy/web'

export const tenancy = createTenancy({
  notAMember: <p>You don't have access to this organization.</p>,
})
```

```tsx title="web/src/Routes.tsx"
<Router useAuth={useAuth} tenancy={tenancy}>
  <PrivateSet wrap={OrgLayout} unauthenticated="login">
    <Route path="/org/{orgSlug}/projects" page={ProjectsPage} name="projects" />
  </PrivateSet>
  <PrivateSet
    wrap={OrgLayout}
    unauthenticated="login"
    unauthorized="projects"
    orgPermission="members.manage"
  >
    <Route path="/org/{orgSlug}/members" page={MembersPage} name="members" />
  </PrivateSet>
</Router>
```

The provider (the per-organization Apollo client, `useCurrentOrg()` and
`useAuth().hasPermission`) is rendered once around the layouts and page of a
`PrivateSet` whose route has `{orgSlug}`, and stays mounted while the user moves
between the organization's pages. A signed-in user who isn't a member sees the
tenancy's `notAMember`. `<PrivateSet orgPermission>` checks a permission of the
membership like `orgRoles` checks its role. A route with `{orgSlug}` outside a
`PrivateSet` is a public page with no organization context, and organization
routes prerender like any private route.

`OrgScope` and `useOrgRoles` are removed from `@cedarjs/tenancy/web`.
`yarn cedar setup tenancy` generates `web/src/tenancy.tsx` instead of the
`OrgScope` component and passes `tenancy` to the `Router`. For an organization
that doesn't come from the path, pass `createTenancy` a `useOrg`.
