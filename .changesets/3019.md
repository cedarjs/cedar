- feat(uploads)!: check what uploaded files are from their bytes, by default
  (#3019) by @Tobbe

Adds `detectContentType(bytes)` to `@cedarjs/uploads`. It tells what kind of
file some bytes are from their contents (their magic bytes), not from the
filename or the type the browser claimed: JPEG, PNG, GIF, WebP, BMP, TIFF,
HEIC/HEIF, AVIF, PDF, MP4, M4A, QuickTime/MOV, WebM, Matroska, OpenDocument
(`.odt`, `.ods`, `.odp`) and Office (`.docx`, `.xlsx`, `.pptx`, with
macro-enabled files reported as their own types). It returns a MIME type, or
`null` for anything it doesn't recognise, and never throws. SVG is deliberately
not detected, since it can carry script.

`acceptedContentType(bytes, accept, claimedType)` checks a file against an
accept list by what its bytes are, and returns the type to store it under.

**Behaviour change.** Uploads now use it by default:

- `POST /upload/fs` checks every file against the profile's
  `allowedMimeTypes` by its bytes.
- `confirmUpload()` and the S3 webhook read the head of each direct-to-S3
  upload and check it against the type declared for it.
- The `uploadFile` service generated by `yarn cedar setup uploads` checks
  database uploads the same way. Existing apps' generated services are not
  changed; see the uploads docs to update yours.

So a file whose bytes aren't what it claims to be (an HTML page sent as
`image/png`) is refused, and a direct upload that fails the check is deleted.
A file the detector doesn't recognise, like a CSV, is still accepted on its
claimed type, through wildcards too, except that types that can carry script
(SVG, HTML, JavaScript, XML) must be listed in `allowedMimeTypes` exactly.
Office files that can carry macros (`.docm`, `.xlsm`, `.pptm` and their
variants, and the old `.doc`, `.xls`, `.ppt`) must be listed exactly too,
whether detected or claimed: a profile allowing `application/*` or `*/*` now
refuses them.

Stored types are normalised to one canonical spelling: `image/jpg` is stored as
`image/jpeg`, `video/x-matroska` as `video/matroska`, `audio/x-m4a` as
`audio/mp4`, and parameters such as `; charset=utf-8` are dropped. Profiles may
list either spelling. Code that compares an upload's `mimeType` to a
non-canonical spelling needs updating.

To keep trusting the claimed type, opt out:

```ts
await server.register(cedarUploadsPlugin, {
  // ...
  verifyContentType: false,
})

// and in your uploads service
createPresignedUpload({ /* ... */ verifyContentType: false })
confirmUpload({ /* ... */ verifyContentType: false })
```

See "Checking what a file really is" in the uploads docs.
