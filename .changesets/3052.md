- fix(jobs): lock jobs with a name unique to the worker process (#3052) by @Tobbe

Each worker locks the jobs it runs with its process title plus the host name and
process id, like `cedar-jobs-worker.default.0 host:app-1 pid:4242`. Two running
workers never share a lock name, so they can't both run the same job: when
two app servers or dev servers ran their workers against one database, workers
with the same title could each run a job, over and over, until their timing
lined up.

A job left locked by a worker that crashed is picked up by any worker once
`maxRuntime` (plus a one-minute grace period) has passed.
