- feat(jobs): pause and resume jobs (#3029) by @Tobbe

A job can be paused and resumed while the app runs, without a code change or a
deploy, for example to stop a nightly job during an incident. Find the job's id
with `yarn cedar jobs list`, then:

```bash
yarn cedar jobs pause 42
yarn cedar jobs resume 42
```

The same is available in code as `jobs.pauseJob(id)`, `jobs.resumeJob(id)` and
`jobs.listJobs()`. Workers don't pick up a paused job. A run in progress
finishes, and a recurring job's next run stays paused. A resumed recurring job
runs next at the next match of its cron, so runs missed while it was paused are
not made up for. A resumed one-off job keeps its run time, and runs right away
if that has passed. Every long-running worker logs a warning listing the paused jobs
in its queues when it starts.

The pause is stored on the job's row: code that deletes and recreates its
recurring jobs creates new rows that aren't paused.

Pausing needs a new column on the `BackgroundJob` model. Add
`pausedAt DateTime?` to it and run `yarn cedar prisma migrate dev`. Apps without
the column keep working as before; pausing a job throws until the column is
there.
