- feat(tenancy): Multi-tenancy support with organizations and memberships

Cedar apps can add "Linear-style" multi-tenancy with one setup command:

```bash
yarn cedar setup tenancy
```

One user account belongs to many organizations, each membership carries its own
role, and a user can work in several organizations at once without logging out.
Tenant scoping is enforced at the Prisma layer, so forgetting `organizationId`
on a query is an error rather than a data leak.

The new `@cedarjs/tenancy` package holds the runtime:

- `createTenancyExtension()` is a Prisma client extension that adds the current
  organization to every query on a tenant-owned model: `where` filters on reads,
  `organizationId` on creates, and a rejection when an update tries to move a
  row to another organization. Nested writes, `connect`/`connectOrCreate`, and
  list `include`/`select` reached from any model are scoped too. Raw SQL is
  refused on a scoped client.
- `db.$forOrg(organizationId)` and `db.$withoutTenant()` are the escape hatches
  for background jobs, scripts, seeds and cross-organization work.
- A query on a tenant-owned model with no organization in scope throws
  `TenantScopeError`.
- `resolveCurrentOrg()` picks the organization per request from the `cedar-org`
  header or an `orgId`/`orgSlug` variable, validates it against the signed-in
  user's memberships, and stores it on `context.currentOrg`. `withTenancy()`
  does the same for plain functions.
- `requireMembership()` and `hasOrgRole()` check roles inside the current
  organization, beside the existing `requireAuth()` and `hasRole()`.
- On the web side, `OrgScope` provides a per-organization Apollo client under
  the organization routes, so each organization gets its own cache and two
  browser tabs can hold two organizations open. `useCurrentOrg()` reads the
  current one.

The setup command adds the `Organization` and `Membership` models, wires the
Prisma extension into `api/src/lib/db`, includes memberships in
`getCurrentUser()`, resolves the organization in the GraphQL context, and
generates an organizations service, a `@requireMembership` directive, an
invitation landing page and a data migration that gives existing users an
organization.

`@cedarjs/web/apollo` gains `useCreateApolloClient()`, which builds an
additional Apollo client from the app's own link chain and cache configuration
with extra headers. `OrgScope` uses it, and apps can use it for any second
client.

See the [multi-tenancy how-to](https://cedarjs.com/docs/how-to/multi-tenancy)
for the full walkthrough and the
[tenancy reference](https://cedarjs.com/docs/tenancy) for the API.

Single-tenant apps are unaffected: nothing is added to new projects and nothing
runs unless `setup tenancy` has been used.
