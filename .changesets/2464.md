- fix(codegen): Read Prisma model names from the generated models file (#2464)
  by @ladderschool

GraphQL codegen imported the whole generated Prisma client just to read
`Prisma.ModelName` — the only thing it takes from the client. With a TypeScript
client that import fails outright in a CommonJS api, because Node resolves the
`.ts` file as CommonJS and the generated client is ESM:

```
SyntaxError: Cannot use import statement outside a module
```

The failure was swallowed, so the symptom was an `api/types/graphql.d.ts` with
no Prisma models mapped in — an empty `import { } from 'src/lib/db'` and an
empty `AllMappedModels`, leaving every SDL type without the fields it should
have inherited through `MergePrismaWithSdlTypes`.

Model names now come from the generated `models.<ext>` barrel that sits next to
the client, resolved with the same output-dir and extension logic as the client
itself. JavaScript clients are unchanged.
