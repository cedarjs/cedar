- fix(codegen): type the BigInt scalar as bigint on the api side (#3265) by @Tobbe

On the api side, generated GraphQL types map the `BigInt` scalar to
`{ input: bigint | number; output: bigint | number; }`. That means resolvers can
return the `bigint` values Prisma reads from `BigInt` columns. Inputs are typed
`bigint | number` because graphql-scalars' `BigIntResolver` parses safe integers
to `number` and larger values (or all values, when `BigInt.prototype.toJSON` is
patched) to `bigint`. This is a type-level breaking change: api code that does
number arithmetic on a `BigInt` argument, like `args.size + 1`, needs a
`typeof` check or an explicit conversion. For integer arithmetic, convert with
`BigInt(args.size)` and use `bigint` operands (`BigInt(args.size) + 1n`).
`Number(args.size)` rounds values beyond `Number.MAX_SAFE_INTEGER`, which are the
values that arrive as `bigint`, so only use it for values known to be in the
safe integer range. The web-side types don't change.
