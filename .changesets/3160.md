- feat(tenancy): permissions on top of roles (#3160) by @Tobbe

Roles map to permissions in one place, and fields ask for a permission instead
of listing roles:

```ts title="packages/permissions/src/index.ts"
export const permissions = definePermissions({
  permissions: {
    'organization.read': {
      description: 'See the organization and its members',
    },
    'members.manage': {
      description: 'Invite members and remove them',
    },
  },
  roles: {
    owner: ['organization.read', 'members.manage'],
    admin: ['organization.read', 'members.manage'],
    member: ['organization.read'],
  },
  user: [],
})
```

```ts title="api/src/lib/permissions.ts"
export const {
  hasPermission,
  requirePermission,
  permissionsOf,
  withPermissions,
} = createPermissions(permissions)
```

```graphql
inviteMember(input: InviteMemberInput!): Invitation!
  @requirePermission(permission: "members.manage")
```

Adding a role is one entry in `roles`, and it gets only what its list says.
Permission names are typed from the definitions, and each has a description.
The definitions live in a package shared by the api and web sides, so the web
can list them (e.g. on an admin page), and `permissionsOf(membership)` is the
one place the api works out what a membership may do. `withPermissions` in `getCurrentUser`
gives each membership its permissions, which `useAuth().hasPermission()` and
`OrgScope`'s `permission` prop check on the web.
`yarn cedar setup tenancy` generates the package (turning on
`experimental.packagesWorkspace`), the checks and the directive.
