- feat(tenancy): permissions on top of roles (#3160) by @Tobbe

Roles map to permissions in one place, and fields ask for a permission instead
of listing roles:

```ts title="api/src/lib/permissions.ts"
export const { can, requirePermission, permissionsOf, withPermissions } =
  createPermissions({
    roles: {
      owner: ['organization.read', 'members.manage'],
      admin: ['organization.read', 'members.manage'],
      member: ['organization.read'],
    },
    user: [],
  })
```

```graphql
inviteMember(input: InviteMemberInput!): Invitation!
  @requirePermission(permission: "members.manage")
```

Adding a role is one entry in the map, and it gets only what its list says.
Permission names are typed from the map. `withPermissions` in `getCurrentUser`
gives each membership its permissions, which `useCan()` from
`@cedarjs/tenancy/web` and `OrgScope`'s `permission` prop check on the web.
`yarn cedar setup tenancy` generates the map and the directive.
