- fix(dbAuth): Support SimpleWebAuthn v13 and reject unverified assertions
  (#2508) by @ladderschool

`DbAuthHandler` was calling SimpleWebAuthn with the API that v11 renamed, so
dbAuth's WebAuthn flows stopped working on any project past v10. Registration
called `create()` with `id: undefined` and Prisma rejected it; authentication
threw on an undefined `credential`. Both surfaced as a 400, and since the
`webAuthn` cookie is only set after a successful registration,
`WebAuthnClient.isEnabled()` never returned true either.

Users on `@simplewebauthn/server@^10` need to upgrade to:

- `@simplewebauthn/server@13.3.3`
- `@simplewebauthn/browser@13.3.0`

And remove the dependency

- `@simplewebauthn/types` — v11 folded those types back into
  `@simplewebauthn/server`

`@cedarjs/auth-dbauth-api` now declares `@simplewebauthn/server@^13.0.0` as an
optional peer dependency, so a mismatched version is a package-manager warning
rather than a runtime failure. It is optional because projects that never ran
`setup auth dbAuth --webauthn` do not install the library.

`webAuthnAuthenticate()` also issued the login cookies whether or not the
assertion verified — `_loginResponse()` ran unconditionally and `_ok()` returns
200 regardless of the body, so a response whose signature did not match the
stored public key was answered with a session for the credential's owner.
`verifyAuthenticationResponse()` throws for most failure modes but returns
`{ verified: false }` for a signature mismatch. It now throws a `WebAuthnError`
before anything is issued.
